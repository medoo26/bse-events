# نظام الفعاليات المدرسية — مدارس ريادة الأعمال ثنائية اللغة

Next.js 14 (App Router) + Tailwind CSS + Supabase (Realtime).

## التشغيل

1. أنشئ مشروعا في [Supabase](https://supabase.com).
2. من **SQL Editor** شغّل `supabase/schema.sql` كاملا (آمن على قاعدة جديدة أو قديمة، ويرقّيها: يحذف كلمات المرور النصية ويغلق الصلاحيات).
3. انسخ `env.example.txt` إلى `.env.local` واملأه: مفتاحا Supabase، و`SUPABASE_SERVICE_ROLE_KEY` (سري، للخادم فقط)، و`SESSION_SECRET` (نص عشوائي ≥ 32 حرفا)، و`ORGANIZER_CODE`.
4. ثم:

```bash
npm install
npm run dev      # http://localhost:3000
```

عند النشر (Vercel مثلا) أضف نفس المتغيرات في إعدادات المشروع، ولا تضع `SUPABASE_SERVICE_ROLE_KEY` في أي متغير يبدأ بـ `NEXT_PUBLIC_`.

## المسارات

| المسار | الوظيفة |
|---|---|
| `/` | الواجهة الرئيسية (زر الدخول للفعاليات) |
| `/login` | الباركود + دخول الطلاب + دخول المنظمين + مؤقت خمول 120 ثانية |
| `/register` | إنشاء حساب طالب |
| `/student-login`, `/student-dashboard` | دخول الطالب وصفحته (حسابي / أنشطتي / شهاداتي) |
| `/organizer` | الفعاليات والأنشطة وسجلات الأرشيف |
| `/organizer/activity/[id]` | الإدارة الحية: التحضير، Excel، إصدار الشهادات |

## الحذف بعد 48 ساعة

الدالة `cleanup_expired_students()` تعمل كل ساعة: تأخذ أرشيفا (`refresh_activity_archive`) لأنشطة الفعاليات المنتهية، ثم تحذف حسابات الطلاب (وتسجيلاتهم وشهاداتهم) بعد 48 ساعة من `events.end_time`. لا تلمس `events` ولا `activities` ولا `activity_archives`.
إن تعذر تفعيل `pg_cron` تلقائيا: فعّله من Database > Extensions ثم نفّذ:

```sql
select cron.schedule('cleanup-expired-students', '0 * * * *', 'select public.cleanup_expired_students();');
```

## الأمان

- **كلمات المرور:** تُشفَّر بـ bcrypt على الخادم ولا تُخزَّن نصا.
- **المنظم:** يتحقق الخادم من الرمز ويصدر جلسة موقّعة (HMAC) في Cookie من نوع HttpOnly وSameSite=Lax لمدة 8 ساعات. `middleware.ts` يمنع فتح `/organizer/*` دون جلسة، وكل مسارات `/api/organizer/*` تتحقق منها. الرمز لا يوجد في كود المتصفح.
- **حد المحاولات:** رمز المنظم: 5 محاولات خاطئة لكل عنوان IP ثم قفل 15 دقيقة (وسقف عام ضد التخمين الموزع). دخول الطالب: 8 محاولات لكل (IP + اسم مستخدم). تُخزَّن في جدول `auth_attempts`.
- **قاعدة البيانات:** RLS مفعّل بلا أي سياسة لـ anon، وصلاحيات anon/authenticated مسحوبة. كل العمليات عبر خادم Next.js بمفتاح service_role. المتصفح لا يقرأ الجداول إطلاقا، ويستقبل فقط إشعارات Broadcast خالية من البيانات.
- **المدخلات:** تُنظَّف في الخادم (إزالة وسوم HTML وأحرف التحكم وتحديد الأطوال والألوان والإحداثيات)، وReact يهرّب النص عند العرض، وCSP يمنع تحميل أي مصدر غريب.
- **التخزين:** رفع قوالب الشهادات عبر روابط موقعة يصدرها الخادم للمنظم فقط؛ الحاوية تقبل JPEG/PNG وحتى 5MB.
- **ترويسات الأمان:** CSP, X-Frame-Options, HSTS, nosniff, Referrer-Policy.
- **ملاحظة:** إن كانت المدرسة خلف عنوان IP واحد فقفل 5 محاولات للمنظم يشمل ذلك العنوان؛ ينتظر المنظم 15 دقيقة أو يستخدم شبكة أخرى.
